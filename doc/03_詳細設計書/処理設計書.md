## 2. クラス設計

### 2.1 パッケージ構成
```
com.sepant
├─ SepantApplication.java
├─ controller   … @Controller。リクエストの受付、入力チェック、画面の表示
├─ form         … 画面の入力値を受け取るフォームクラス
├─ validator    … 相関チェック（Spring Validator）
├─ service      … @Service。業務処理、精算済みチェック、トランザクション
│   └─ calc     … 精算額の計算（DBに依存しない）
├─ repository   … @Repository。Spring Data JDBCのリポジトリ
├─ entity       … テーブルに対応するエンティティ
├─ dto          … 画面に渡す表示用データ、計算結果
├─ common       … 区分の列挙型、年月・金額の変換
└─ exception    … 業務例外と、例外のハンドリング
```

- パッケージのルート（`com.sepant`）は、リポジトリ作成時に決める。

## 3. 機能ごとの処理

### 3.1 F-03・F-05 ホーム表示（GET /home）
1. `ym`がなければ当月とする。`YYYYMM`形式でなければエラー画面を表示する。
2. 費目マスタを表示順に取得する。
3. 対象月の変動費明細を取得し、費目×利用者で合計する。区分01・02の費目は、明細がなくても0円の行を作る。
4. 対象月に有効な固定設定を取得し、区分03〜06に分ける。
5. 区分03・04・06の費目のうち、有効な固定設定がないものについて警告（W001・W002）を作る。
6. `SeisanService.calculate(ym)`で精算額・向きを求める。
7. `SeisanService.isSettled(ym)`で精算状況を求める。
8. HomeViewにまとめて`home.html`を表示する。

### 3.2 F-02 支払い登録（GET・POST /payment）
**表示（GET）**
1. `ym`・`userId`・`himokuCd`の存在と形式をチェックする。費目の区分が01・02でなければエラー画面を表示する。
2. 精算済みの月であれば、ホームへリダイレクトしてE701を表示する。
3. セルの明細を支払日順に取得してフォームに詰める。0件なら空の行を1行追加する。

**行の追加・削除（POST、addRow・removeRow）**
1. 入力チェックをせずに、`meisaiList`に空の行を追加する、または指定の行を削除する。
2. 同じ画面を再表示する。

**登録（POST、register）**
1. Bean ValidationとPaymentFormValidatorでチェックし、エラーがあれば入力内容を残して再表示する。
2. `PaymentService.replace(form)`を呼ぶ。（`@Transactional`）
   1. 精算済みの月であればSeisanzumiExceptionを投げる。
   2. `deleteCell(ym, userId, himokuCd)`でセルの明細を全て削除する。
   3. フォームの行をエンティティに変換し、`saveAll`で登録する。
3. `/complete?type=payment&ym=対象月`へリダイレクトする。

### 3.3 F-04 固定設定登録（GET・POST /settei）
**表示（GET）**
1. 全ての固定設定を取得し、費目の区分でセクション（koteiList・shunyuList・tobanList）に分ける。
2. 各セクション内を、費目の表示順・開始月順に並べる。年月は`YYYY-MM`に変換して表示する。

**行の追加・削除（POST、addRow・removeRow）**
1. `addRow`の値（リスト名）のリストに空の行を追加する。`removeRow`の値（`リスト名:行番号`）の行を削除する。
2. 同じ画面を再表示する。

**登録（POST、register）**
1. Bean ValidationとSetteiFormValidatorでチェックし、エラーがあれば入力内容を残して再表示する。
2. `SetteiService.replaceAll(form)`を呼ぶ。（`@Transactional`）
   1. `deleteAll()`で固定設定を全て削除する。
   2. 3つのセクションの行をまとめてエンティティに変換し（年月は`YYYYMM`に変換）、`saveAll`で登録する。
3. `/complete?type=settei&ym=対象月`へリダイレクトする。

### 3.4 F-05・F-06 計算結果（GET /result）
1. `SeisanService.calculate(ym)`で計算結果を求める。
   1. 費目マスタ、対象月の変動費明細、対象月に有効な固定設定を取得する。
   2. SeisanInput（4.2）に変換する。
   3. `SeisanCalculator.calculate(input)`で計算する。
2. `isSettled(ym)`がtrueなら「精算する」を表示しない。
3. `result.html`を表示する。

### 3.5 F-07 精算（GET /seisan/confirm、POST /seisan）
**確認（GET）**
1. 精算済みの月であれば、ホームへリダイレクトしてE701を表示する。
2. `calculate(ym)`で精算額・向きを求め、`confirm.html`を表示する。

**精算（POST）**
1. `SeisanService.settle(ym)`を呼ぶ。（`@Transactional`）
   1. 精算済みの月であればSeisanzumiExceptionを投げる。
   2. t_seisanに対象年月と当日の日付を登録する。
2. `/complete?type=seisan&ym=対象月`へリダイレクトする。

## 4. 精算額の計算

### 4.1 計算の考え方
- 精算額は、夫について「実際に払った額（支払額）」と「払うべき額（負担額）」の差で求める。
- 夫と妻の差額の合計は必ず0になる（夫がプラスなら、妻は同額のマイナス）。

### 4.2 入力（SeisanInput）
| 項目 | 内容 | 取得元 |
|---|---|---|
| 支払い | 利用者・区分・金額の一覧 | 区分01・02:変動費明細、区分03〜06:対象月に有効な固定設定 |

- 固定設定の利用者は、区分03・04では支払った人、区分05では受け取った人、区分06では担当者として扱う。

### 4.3 計算の手順
| No | 計算項目 | 式 | 端数 |
|---|---|---|---|
| 1 | 折半対象の合計 S | 区分01・03の金額の合計 | — |
| 2 | 収入の合計 I | 区分05の金額の合計 | — |
| 3 | 折半額（妻） | (S − I) ÷ 2 | 切り捨て |
| 4 | 折半額（夫） | (S − I) − 折半額（妻） | 端数は夫が持つ |
| 5 | 支払額（各自） | 自分の区分01・03 ＋ 自分の区分02・04 − 自分の区分05 | — |
| 6 | 負担額（各自） | 自分の折半額 ＋ 相手の区分02・04 − 自分の区分06 ＋ 相手の区分06 | — |
| 7 | 差額（夫） | 夫の支払額 − 夫の負担額 | — |
| 8 | 精算の向き | 差額（夫）がプラスなら妻→夫、マイナスなら夫→妻、0なら精算なし | — |
| 9 | 精算額 | 差額（夫）の絶対値 | — |

- 折半額の切り捨ては、S − Iがマイナスの場合も「妻の折半額 ≦ 夫の折半額」となるように`Math.floorDiv`で計算する。
- 当番の金額は、担当者の負担額を減らし、相手の負担額を同じ額だけ増やす。2,000円の当番では負担額の差が4,000円開き、実際に受け渡す額は2,000円になる。
- 金額は全て`int`（円）で扱う。

### 4.4 計算例
| 区分 | 費目 | 夫 | 妻 |
|---|---|---|---|
| 01 折半（変動費） | 食費 | 20,000 | 15,000 |
| 01 折半（変動費） | 日用品 | | 5,001 |
| 03 折半（固定費） | 家賃・NHK・Wi-Fi | 86,100 | |
| 02 立替（変動費） | 携帯代 | 3,000 | |
| 04 立替（固定費） | 結婚資金 | | 10,000 |
| 05 収入 | 住居手当 | 20,000 | |
| 06 当番 | 皿洗い | 2,000 | |
| 06 当番 | 夕食 | | 2,000 |

| No | 計算項目 | 夫 | 妻 |
|---|---|---|---|
| 1 | S | 126,101 | |
| 2 | I | 20,000 | |
| 3・4 | 折半額（S − I = 106,101） | 53,051 | 53,050 |
| 5 | 支払額 | 106,100 + 3,000 − 20,000 = 89,100 | 20,001 + 10,000 = 30,001 |
| 6 | 負担額 | 53,051 + 10,000 − 2,000 + 2,000 = 63,051 | 53,050 + 3,000 − 2,000 + 2,000 = 56,050 |
| 7 | 差額 | 26,049 | △26,049 |
| 8・9 | 結果 | 妻→夫（夫◀妻）26,049円 | |

### 4.5 単体テストの観点（SeisanCalculator）
| No | 観点 | 確認内容 |
|---|---|---|
| 1 | 折半のみ | 夫だけが払った場合、妻→夫に半額になる。 |
| 2 | 端数 | S − Iが奇数のとき、夫の折半額が1円多くなる。 |
| 3 | 収入 | 収入を受け取った人の支払額から収入が引かれる。 |
| 4 | 立替 | 立て替えた全額が相手の負担額に加わる。 |
| 5 | 当番 | 2,000円の当番で、精算額が2,000円動く。 |
| 6 | 差額0 | 精算の向きが「精算なし」になる。 |
| 7 | 合計0 | どの組み合わせでも、夫と妻の差額の合計が0になる。 |
| 8 | 計算例 | 4.4の入力で、妻→夫26,049円になる。 |

## 5. チェック処理

### 5.1 年月パラメータ
- `ym`は`^[0-9]{4}(0[1-9]|1[0-2])$`に一致すること。一致しなければエラー画面（E901）を表示する。

### 5.2 精算済みチェック
- PaymentService・SeisanServiceの登録処理の先頭で、`SeisanRepository.existsById(ym)`がtrueならSeisanzumiExceptionを投げる。
- 画面での非活性・リンクの非表示に加えて、登録処理でもチェックする（URLを直接送られても登録しないため）。

### 5.3 支払日のチェック
- `YearMonth.from(shiharaiDd)`が対象年月と一致すること。

### 5.4 期間の重複チェック
1. 全セクションの行を費目CDでグループに分ける。
2. グループ内を開始月の昇順に並べる。
3. 隣り合う2行で、前の行の終了月 ≧ 後の行の開始月であれば重複とする（E103、{0}は費目名）。

## 6. SQL

### 6.1 セルの明細の取得（findCell）
```sql
SELECT * FROM t_hendohi_meisai
 WHERE taisho_yymm = :ym AND user_id = :userId AND himoku_cd = :himokuCd
 ORDER BY shiharai_dd, meisai_id
```

### 6.2 セルの明細の削除（deleteCell）
```sql
DELETE FROM t_hendohi_meisai
 WHERE taisho_yymm = :ym AND user_id = :userId AND himoku_cd = :himokuCd
```

### 6.3 対象月に有効な固定設定（findValid）
```sql
SELECT * FROM t_kotei_settei
 WHERE kaishi_mm <= :ym AND shuryo_mm >= :ym
```

## 7. トランザクション
| メソッド | 範囲 | 理由 |
|---|---|---|
| PaymentService.replace | 精算済みチェック〜削除〜登録 | 削除だけ成功して明細が消えるのを防ぐ。 |
| SetteiService.replaceAll | 全削除〜全登録 | 同上。 |
| SeisanService.settle | 精算済みチェック〜登録 | 精算済みの判定と登録を1つの処理にする。 |

- 読み取りだけのメソッドには`@Transactional(readOnly = true)`を付ける。
